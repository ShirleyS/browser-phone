## Browser Phone architecture rules
- Public API lives only in `src/routes/api/public/v1/*` delegating to `src/server/bp/handlers.ts`; every handler authenticates with a scoped bearer token itself because `/api/public` bypasses platform auth.
- Quota/session creation must go through the `bp_create_session` SQL function so the daily/concurrency limits stay atomic.
- All outbound webhook calls go through `deliverWebhook` (SSRF re-check, no redirects, HMAC signature).
- Phone behavior lives in the framework-agnostic `PhoneEngine` with injected deps so offline mode/replay can be proven network-free in tests.
- Anything rendered during SSR must be deterministic; read `window`/random values in `useEffect`.
- `public/downloads/browser-phone-source.zip` is generated by `scripts/build-source-archive.mjs` (allowlist); re-run it after source changes.

- Every inbox insert uses bp_insert_message (session row lock before sequence allocation); direct service-role insertion is denied to avoid out-of-order cursor loss.
- Event forwarding uses lease-fenced claim/finish RPCs and persists successful signaling responses; receivers still deduplicate stable IDs across timeout/crash recovery.
- Pairing verification is a single row-locked RPC to enforce the attempt bound under concurrency.
- Outbound delivery requires either an operator-attested independently enforced public-only egress boundary or the native Node startup-installed checked-address-pinned HTTPS transport; hosted DoH is not coupled to fetch resolution.
- Engine generation fences and request cancellation invalidate asynchronous work on lifecycle transitions; shared chat creation avoids first-send session races.
- Voice config validation is shared by signaling server and browser before microphone access; opaque credentials with unverified destinations fail closed.

- Inbox pages measure the complete serialized UTF-8 envelope before adding rows and only advance cursors through included rows, staying below the client cap.
- Call deadlines are scoped to exact call generation/session and cleared by hangup; chat expiration cannot terminate unrelated calls.
- Node-only DNS/socket code stays in deployment scripts and is injected at startup; Worker bundles contain only the browser-safe transport interface.
